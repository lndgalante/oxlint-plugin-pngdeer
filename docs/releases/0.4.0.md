# 0.4.0

Check image savings before configuring a linter, and control how much work the rule does during targeted lints.

## New

- `npx oxlint-plugin-pngdeer --check [IMAGE|DIR...]` checks files or directories without changing images. It reports potential savings and warms the cache shared by oxlint and ESLint. No paths means the current directory.
- Checks exit `0` when clean, `1` when an image meets both savings thresholds, and `2` when invalid arguments, unreadable inputs or engine failures prevent a complete check.
- Check options include `--target`, `--min-saved-bytes`, `--min-saved-percent`, repeatable `--exclude`, and `--cache-dir`. The command does not read linter configuration; pass nondefault settings explicitly.
- The rule accepts `scan: "referenced"` for images named by linted files, and `exclude` for project-relative paths and simple `*`, `**`, `?` patterns. Exclusions apply to direct references and summaries too.
- Successful cached measurements can be copied into a committed cache with `--check --cache-dir .pngdeer`; failed measurements remain local.

## Fixes

- Prevent worker startup hangs when an ESLint caller uses Node's `--input-type` option.
- Preserve symlinks when shrinking images, and include symlinked image files in directory checks.
- Correct TypeScript alias precedence, fallback paths, inherited configuration and generated-config refreshes.
- Let ESLint handle disable directives so used comments are not reported as unused. Resolve `lintText()` references from ESLint's configured working directory.
- Refresh cached content keys after same-size replacements that preserve modification time, and apply savings thresholds before rounding.
- Honor constrained-container memory budgets, preserve quality targets in summary commands, and reject malformed flagged manifests.
- Protect shared images from bulk compression when another enabled reference requires a stricter target that did not warn, or when references mix automatic and fixed targets. The summary explains which images were left out.
- Generate literal PowerShell commands for unusual Windows filenames, bypassing npm's batch shim so shell expansion cannot change the image path.

## Defaults and compatibility

Project scanning remains the default. In the small benchmark, a cold one-file lint took 0.92 seconds with referenced scanning versus 5.7 seconds with project scanning. A full cold lint was faster with project scanning: 5.6 seconds versus 16.8 seconds. Choose the scope for your workflow; cached full lints took about 0.14 seconds in either mode.

The bundled engine is unchanged, so existing measurements remain usable. Compression still requires an explicit command and is lossy. Checks leave the lint's `--flagged` list unchanged. Node, oxlint and ESLint version requirements are unchanged.

Package installation, CLI behavior, the bundled WASM engine, and cache reuse by both linters are now checked from the actual npm tarball in CI and before publishing.

Pinned source and compiler provenance, a container build that compares two clean engine builds, and repeatable trials on public-project image samples are included in the repository. Their results and limitations are documented in `engine/README.md` and `bench/TRIALS.md`.
