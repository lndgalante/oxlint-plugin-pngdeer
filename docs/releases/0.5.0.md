# 0.5.0

Fixes from a review of 0.4.0. The summary no longer calls used images unused, `--check` no longer passes a monorepo it didn't look into, a lint that runs out of time fails instead of passing, and shrunk PNGs keep their orientation. ESLint gets a recommended config.

## New

- `pngdeer.configs.recommended` turns the rule on at `"warn"` in ESLint, for the files the rest of your config lints. It sets no `files`, so it never adds JSX or TypeScript your config doesn't parse. Put it in your config array, or in `extends` with ESLint's `defineConfig`. It is typed, as part of the new `PngdeerPlugin` type.
- `--check` words each image's quality the way the shrink command does, prints the biggest savings last, next to the totals, and ends with the commands that preview the biggest saving as a new file and shrink the biggest images (up to 10) in place.
- `--check` names the nested packages it skipped, with the command that checks them with the same options.
- Progress in CI logs: off a terminal, a first run prints `pngdeer: measured N of M images...` every 30 s. On a terminal, `--check` now counts images as it measures them, as the lint does.
- In the summary, images that no linted JS or TS names can say `named in <file>` (JS or TS the run didn't lint or couldn't resolve) or `a Next.js metadata file`. The hidden rows of that list get a total, and the list says how to stop listing an image you keep: add its path, from its project's folder, to `exclude`. When the run linted no file of the kind that names an image, like an ESLint config that leaves out `.tsx` files, the summary says so. The quality legend now covers "below 70 visibly different".
- In editors, the open file's own images are measured first, so its warnings don't wait for the whole project's.
- A lint waiting for another process's batch, like your editor's, says so, and names the lock to delete if nothing is running.
- With `-o`, the command's result line names both files.

## Fixes

- `--check` at a monorepo's root, or on a folder holding only packages, skipped every package and reported a clean check with exit `0`. It now exits `2` and names the packages.
- After a one-file lint, lint-staged, a parse error or a bare path like `"images/hero.png"`, the summary said "nothing names it" for images that code uses, and suggested deleting them. It now finds them in JS and TS too, matches an image's path before its bare file name (so `social-card.png` no longer matches `docusaurus-social-card.png`), and suggests deleting only images nothing names.
- A first run that passed 15 minutes stopped and let the lint pass, even with the rule at `"error"`. It now reports one problem at the rule's severity, saying how many images it didn't measure (with ESLint's `--concurrency`, one per thread). If comments turn the rule off wherever that problem would go, pngdeer says so on stderr and the lint fails, even at `"warn"`.
- A batch stopped by the time limit, or one that died in an editor (out of memory, say), left its lock behind, and the same process's later batches waited on it for up to 15 minutes. The lock is now removed.
- A PNG that EXIF turns (macOS `sips` writes these from rotated photos) came out unturned. Shrunk PNGs now keep the EXIF orientation, as JPEGs already did.
- A grayscale PNG with a color profile came out darker, because pngdeer writes it as a palette PNG that keeps the gray profile. Such images are now skipped until pngdeer keeps them gray.
- Setting `cacheDir` after a first lint left the committed folder without what that lint had measured. A lint now copies those results into it.
- With `eslint --cache`, the summary contradicted the replayed warnings and emptied `--flagged`'s list. Now one line says there is no summary, and the list from the last run without `--cache` stays. `--flagged` with no list says to lint without `--cache`.
- A project in a folder named like a language server (a clone of yaml-language-server, say) linted as an editor: it never measured and passed. Only the linter's own script name counts now.
- `%`-escaped paths like `/my%20photo.png` are found. An image that code names in another case or Unicode form than the disk is measured once, and counted once in warnings, the summary and `--flagged`.
- Copies of one image are measured once, the count reaches its total, and ESLint's `--concurrency` prints one "measuring" line.
- `-o` with a folder fails at once, instead of compressing the image and then failing. In `--check`, a cache folder that can't be written is named once, instead of each image reading "permission denied".

## Defaults and compatibility

The cache format changed, so the first lint or `--check` after upgrading measures every image again, once per project and target. The engine is unchanged. A committed `.pngdeer` keeps old entries that nothing reads: delete it, fill it again, and commit it:

```bash
npx oxlint-plugin-pngdeer --check --cache-dir .pngdeer
```

Pass the rule's `--target` if it sets one, and in a monorepo, name each package's folder.

The oxlint peer range is now `>=1.60.0 <2` (it was `>=1.90.0 <2`), so a project that pins oxlint between 1.60 and 1.89, like Vite+ 1.4 with 1.89.0, installs without a peer conflict. The full tests, the language-server test and the package check passed on oxlint 1.60.0, 1.89.0 and 1.90.0, and CI now runs 1.60.0 and 1.89.0 as well as the newest. Versions in between weren't each tested. Node and ESLint requirements are unchanged.

`--check` at a workspace root used to exit `0` and now exits `2`; when the root has images of its own, the exit code still follows those. It also exits `2` on a grayscale PNG with a color profile that is big enough to measure, which 0.4.0 measured. Its output changed too: the per-image lines are sorted by saving and carry the quality in words, the last lines are new, and a missing path reads "no such file or folder". Scripts that parse it need updating.

Summary rows that said "nothing names it" or "used in" may now say "named in" or "a Next.js metadata file", and the note about deleting unused images appears only when a row says "nothing names it".

Releases now publish from a job that runs no dependency code. CI also tests Node 26 and Node 20.19.0, the oldest supported.
